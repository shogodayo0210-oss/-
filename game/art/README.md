## 0. 何を参照して、何を採らないか

| 参照 | 採るもの | 採らないもの |
| --- | --- | --- |
| **ドラゴンクエスト** | **系統でシルエットを共有する。** スライム系は丸い、ドラゴン系は翼 ―― 新キャラでも一目で系統が分かる。これを `family`（人/獣/機械/不死/精霊）でやる | 正面向きの立ち絵。こちらは横スクロールなので側面固定 |
| **にゃんこ大戦争** | **横向き固定・楕円の影1枚・シルエット優先。** 30体が同時に並んでも役割が読める作り。極端に単純化した影の扱いはそのまま真似る | 頭身の崩し方。こちらはもう少し細かいドットで、崩しは中程度に留める |
| **ポケモン** | **役割が色で分かること。** タイプが色で伝わるのと同じで、アクセント色に役割を持たせる。BW世代の96pxに近い階調感 | 正面シンボル的な構図。戦闘中は側面しか見えない |

**共通して採るのは1つ。** 3作とも、**小さく表示しても「それが何か」が分かる**。
シルエットが第一で、描き込みは二番目。

## 1. 解像度

| 対象 | 実寸 | 画面での扱い |
| --- | ---: | --- |
| ユニット | **48 × 48** | 等倍〜2倍。画面高さのおよそ 1/6 |
| 拠点（アバター） | **64 × 64** | レーンの両端 |
| 切り札 | **96 × 96** | 出た瞬間に大きさで分かる |
| カードのアイコン | 32 × 32 | UI上の小サイズ |

**「細かめ」の基準**：48pxで**目が2px**、**装備が識別できる**粒度。
にゃんこ大戦争より細かく、ポケモンBW（96px）より粗い、その中間に置く。

1レーンは 120m。画面に一度に収まるのはおよそ 60〜80m ぶんで、
**同時に最大30体**が並ぶ（`max_units_per_side`）。この密度で潰れないことが条件。

## 2. パレット

**6色1組を全系統で固定する**（`palette.json`）。

| 役割 | 使いどころ |
| --- | --- |
| `outline` | 輪郭。**真っ黒にしない** ―― その系統の暗色に寄せると硬くならない |
| `shadow` | 下面と奥 |
| `base` | 本体 |
| `light` | 上面。光は左上から |
| `accent` | 得物・目・系統の記号。**役割を示す色** |
| `dark_accent` | アクセントの影、刃の厚み、攻城具 |

色数と役割の位置を揃えてあるので、**描き手が増えても質感が揃う**。
系統ごとに変えるのは色相だけ。

| 系統 | 方向 | 形の記号 |
| --- | --- | --- |
| 人 | 青灰 ＋ 金 | 兜、直線的な装備 |
| 獣 | 茶 ＋ 橙 | 耳と尾 |
| 機械 | 灰 ＋ 水色 | 角張った胴、アンテナ |
| 不死 | 紫 ＋ 緑 | 裾がほつれる、目が光る |
| 精霊 | 青緑 ＋ 淡黄 | 脚が無く浮く |

**`family` は見た目だけの区分**で、数字にも戦闘にも影響しない。
役割はあくまで数字が決める（設計書2章）。

## 3. シルエットの規約

**数字がそのまま形になる。** ここが指針の核心。

| データ | 見た目 |
| --- | --- |
| 対拠点倍率 ≤ 0.6（＝壁） | **横に広く低い。前に盾**を構える |
| 攻撃範囲の手前 > 0（＝後方範囲） | **上を向いた砲身。** 死角があることが形で分かる |
| 攻撃範囲の奥 > 50（＝遠距離） | **細く高い。得物が長い**（長さは射程に比例） |
| 移動速度が速い | **前傾。** 重心が後ろ足に乗る |
| コストが高い | **大きい。** キャンバスを埋める |
| 対拠点倍率 ≥ 1.3 | **背中に攻城具**を背負う |
| 対壁倍率 > 1.5 | **刃が厚い**（壁を割る道具に見せる） |

**なぜ紐づけるか。** 初見の人が「見ただけで何をするユニットか」を当てられるように
するため。ドラクエもにゃんこもポケモンも、ここが強い。
ルールブックを読ませる前に、**絵が役割を説明する**状態を作る。

この規約は文章だけでなく、`tools/sprites.py` が**実際にこの通り描く**。
絵描きが入る時は、その出力が仕様書代わりになる。

## 4. アニメーション

| 動作 | 枚数 | 備考 |
| --- | ---: | --- |
| 待機 | 2 | 呼吸。ループ |
| 歩行 | 4 | ループ |
| 攻撃 | **4** | 配分を `attack_windup_sec` に一致させる（下記） |
| 被弾 | 1 | 色を明るく飛ばすだけでもよい |
| 退場 | 2 | |
| **計** | **13枚** | 1体あたり |

### 攻撃アニメの配分が肝

**振りかぶりの長さを、データの `attack_windup_sec` に一致させる。**

| ユニット | 発生 | 振りかぶり | 当たり | 戻り |
| --- | ---: | ---: | ---: | ---: |
| 臼砲 | 0.80秒 | 3枚 | 1枚 | ―― |
| 砲手 | 0.70秒 | 3枚 | 1枚 | ―― |
| 双剣 | 0.10秒 | 1枚（ほぼ無し） | 1枚 | 2枚 |
| 兵卒 | 0.15秒 | 1枚 | 1枚 | 2枚 |

**ここがずれると、見切りの読み合いが嘘になる。**
設計書7.5で「大きい一撃は必ず発生0.6秒以上」と決めたのは、
*振り始めが見えたら反応できる*ようにするため。
絵が先に当たったり、逆に振りかぶりが見えないと、その約束が破れる。

**カードの詠唱も同じ**。0.5〜0.9秒の詠唱には、足元のサークルが
その秒数をかけて広がる演出を当てる。見切り（0.3秒）を合わせる相手がこれ。

## 5. 拠点（アバター）

アバターは**殴られる当事者**なので、**城と人が一体**になった絵にする。
画面端に立っているだけの飾りではない。

見た目の方向づけ（`look`）は6種。数字には影響しない。

| look | 飾り | 該当アバター |
| --- | --- | --- |
| **可憐** | リボン。淡い桃色 | 姫・獣使い |
| **剛力** | 角。赤茶と金 | 不動・豪傑 |
| **知性** | 尖り帽。青と水色 | 斥候・軍師・術師・職人・隠者 |
| **俊敏** | なびく布。緑と淡黄 | 疾風 |
| **怪異** | 仮面。紫と黄緑 | 賭博師 |
| **王道** | 王冠。金 | 統率 |

拠点HPが減るほど**塔が崩れる**（3段階）。「あとどれだけ削れば勝てるか」を
数字ではなく形で見せる。

## 6. 発注の単位

1体あたりの流れ：

```
data の数字（役割が決まっている）
  → ラフ（シルエットだけ。3章の規約に沿っているか確認）
  → ドット（48×48、6色）
  → アニメ13枚
  → 音（攻撃・被弾・退場）
```

**物量の目安**

| | 数 | ×枚数 | 合計 |
| --- | ---: | ---: | ---: |
| ユニット | 32 | 13 | 416枚 |
| 切り札 | 3〜8 | 13 | 39〜104枚 |
| アバター（拠点） | 12 | 崩れ3段階 | 36枚 |
| カードのアイコン | 30 | 1 | 30枚 |
| エフェクト | 〜20 | 4〜8 | 80〜160枚 |

**ここがプロジェクトの物量の大半**になる。
数字と設計は先行しているが、絵は1枚も本番のものが無い。

## 7. いまの仮絵

`tools/sprites.py` が data から仮のドット絵を生成する（依存なし）。

```console
$ python3 game/tools/sprites.py
ユニット 32 / アバター 12 を game/art/out に書き出した
シルエットの内訳: melee 7 / heavy 7 / ranged 6 / wall 5 / fast 5 / mortar 2
```

- `out/units_sheet.png` — 32体の一覧
- `out/avatars_sheet.png` — 12体の一覧
- `out/units/*.png`, `out/avatars/*.png` — 個別

**これは本番の絵ではない。** 目的は2つだけ。

1. 試遊版に**今すぐ何かを映せる**ようにする（絵待ちで開発を止めない）
2. 3章の規約を、文章ではなく**実行できる形**にしておく

絵描きが入ったら、この出力を仕様書として本番の絵に差し替える。
差し替えても data は一切変わらない。
