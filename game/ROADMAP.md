# 工程表 v2 — 削ってから作る

前の版（12ヶ月・5期）を、**5つの手順**にかけ直したもの。

> 1. **要件を疑う。** 要件には必ず**人の名前**を付ける。部署名ではなく。
> 2. **消す。** 消したうちの1割を戻すことにならないなら、消し方が足りない。
> 3. **単純にする。** ただし1と2の**後**。存在すべきでないものを最適化しない。
> 4. **速くする。** 最初の3つの後。
> 5. **自動化する。** 最後。

前の版の一番の問題は、**12ヶ月のうち8ヶ月目まで誰も遊べない**ことだった。
一番大きな不確実性（面白いのか）を、一番後回しにしていた。

## 2. 消す

| 消すもの | 前の見積 | 代わりに | 後 |
| --- | ---: | --- | ---: |
| 通信対戦（リアルタイム） | 6週 | **非同期対戦。** 入力列を送って相手の端末で再生する | 1週 |
| TypeScript移植＋一致試験 | 5週 | **pygbag**（pygameをそのままブラウザで動かす） | 1週 |
| アカウント・戦績保存 | 2週 | ブラウザに置く | 0 |
| マッチング | 1.5週 | **共有コード。** URLに載せて渡す | 0.5週 |
| ストア申請・レーティング | 2週 | Webなので**そもそも要らない** | 0 |
| チュートリアル | 2週 | **初戦のCPU戦がそれ** | 0 |
| 収益化の実装 | 2週 | 遊ばれてから決める | 0 |
| アバター特典26個 | 3週 | **6個。** いま26個中**21個が未実装**（`NOT_SIMULATED`） | 0.5週 |
| 本番アート32体 | 7.5ヶ月 | **12体**（3章） | 5週 |

**削減 24週。** そのうち戻すもの（1割の戻し）：

| 戻すもの | なぜ | 追加 |
| --- | --- | ---: |
| リプレイの記録と検証 | 非同期対戦はこれが本体 | +1週 |
| CPU相手の作り込み | 通信を消したのでCPUが**主な相手**になる | +1.5週 |
| **計** | | **+2.5週** |

戻しが 2.5/24 ＝ **約1割**。手順2の目安ちょうど。
これより戻しが少なければ削り足りず、多ければ削りすぎている。

### 通信対戦を消せる理由

**あなたは一度も「オンライン対戦」と言っていない。** 「1v1」とは言った。
1v1は、同じ端末でも・CPU相手でも・非同期でも成立する。

そして**非同期はほぼタダで手に入る。** シミュレータは既に決定論的で
（固定タイムステップ0.05秒、位置比較にEPS）、試遊版は**通った操作を
入力列として記録している**。相手の入力列を再生すれば同じ試合が再現される。
サーバも同期も要らない。

失うのは「今この瞬間に読み合う」感触。**それが要るかどうかは、
塊Cで実際に配ってから決めればいい。** 先に6週払う理由がない。

## 3. 単純にする

**残ったものだけを単純にする。** 消したものは最適化しない。

### 絵：1体13枚 → 7枚

| | 前 | 後 | 理由 |
| --- | ---: | ---: | --- |
| 待機 | 2 | 1 | 横スクロールで止まっている時間が短い |
| 歩行 | 4 | 3 | 3枚ループで十分に歩いて見える |
| 攻撃 | 4 | 3 | 振り・当たり・戻り。**配分は `attack_windup_sec` に合わせる**（ここは譲らない） |
| 被弾 | 1 | 0 | **色を明るく飛ばすだけ。** 絵は要らない |
| 退場 | 2 | 0 | フェード＋落下。絵は要らない |
| **計** | **13** | **7** | |

### v1に載せるのは12体

データは32体のままでいい（もう出来ている・タダ）。**絵を描くのが12体**。
壁2・接近戦3・高速2・遠距離2・後方範囲1・大型2。
残り20体はv2で足す ―― データがあるので、絵が上がった順に増える。

| | 前 | 後 |
| --- | ---: | ---: |
| ユニット | 416枚 | **84枚**（12×7） |
| 切り札 | 39枚 | **7枚**（1体） |
| 拠点 | 36枚 | **9枚**（3体×3段階） |
| アイコン | 30枚 | **12枚** |
| エフェクト | 120枚 | **40枚** |
| **計** | **641枚** | **152枚** |

**7.5ヶ月 → 5週。** ここが工程表で一番大きく動いた数字。

## 4. 速くする

**測る対象を1つに決める：「面白いか」の答えが出るまでの時間。**

| | 前の版 | いま |
| --- | ---: | ---: |
| 面白いかの答えが出るまで | **8ヶ月**（第3期の終わり） | **1週**（塊A） |
| 他人が触れるまで | 8ヶ月 | **9週**（塊C） |
| データを直して試すまで | 数分 | 数分（既に速い） |

他人が触るまでの摩擦も、いまは `pip install` が要る。
これが **URLを送るだけ**になると、試遊が週2人から週20人になる。
**pygbag が効くのはそこ**であって、配信のためではない。

## 5. 自動化する

**まだやらない。形が固まっていないものを自動化すると、間違った形が固まる。**

塊Dに入ってから、この2つだけ：

- **バランスの夜間実行。** `--all --repeat` を回して、拠点への与ダメージ差を記録。
  data を触ったら翌朝に差分が出る
- **仮絵の再生成。** `sprites.py` は既にdataから描くので、
  数字を変えたらシルエットが自動で追従する

## 優先順位

**潰す不確実性の順に並べる。** 高いのは「致命的で・まだ分からず・安く試せる」もの。

| 順 | 不確実性 | 致命的か | いま分かるか | 試す値段 | どこで |
| ---: | --- | --- | --- | --- | --- |
| **1** | **面白くない** | 致命的 | 未知 | **1週** | 塊A |
| **2** | **続かない**（1回遊んで終わり） | 致命的 | 未知 | 9週 | 塊C |
| 3 | 絵が間に合わない | 日程 | 既知 | 金で解ける | 塊F |
| 4 | 数字が収束しない | 品質 | 半分既知 | 2週 | 塊D |
| 5 | 技術（Web化） | 日程 | 未知 | 1週 | 塊C |
| 6 | 出す手続き | 低 | 既知 | 1週 | 塊E |

**1が答えを出すまで、2〜6には一切手を付けない。**
面白くないなら、残り全部が無駄になる。

## 塊A：択を成立させる（1週）

**最優先。他の全部がこれ待ち。**

### なぜ、いまの試遊版では測れないか

前回作ったものには、測るための穴が2つある。

| 穴 | いまの状態 | なぜ致命的か |
| --- | --- | --- |
| **プレイヤーが成長できない** | 出撃ボタンだけ。レベルを上げる手が無い | 設計書1章の「試合中の択は2つ（出すか・育てるか）」の**片方が存在しない**。これでは面白さを測れない |
| **相手だけ本気** | 相手＝8種＋カード3枚＋切り札＋成長／自分＝1種のみ | 比べる対象になっていない。負けても**何が悪いのか分からない** |

### 工程

| | やること | 目安 | 終わりの形 |
| --- | --- | ---: | --- |
| A-1 | **成長ボタンを付ける。** `Controller` に `upgrade` を足す。育成6秒のあいだ全ボタンが止まることも画面に出す | 0.5日 | 押すと Lv が上がり、その間なにも出せない |
| A-2 | **試遊用の6種を選ぶ。** 壁・接近戦・遠距離・後方範囲・高速・高コストを1つずつ。`data/preset_six.json` | 0.5日 | 6種の役割が数字で違う |
| A-3 | **相手も同じ6種にする。** `--enemy-roster same` | 0.5日 | 同じ持ち物で戦う |
| A-4 | **10試合遊ぶ。** 1試合ごとに終わった直後に1行書く | 2日 | 記録が10行 |
| A-5 | **判定する** | 0.5日 | 下の表が埋まる |

### 判定のしかた

「面白い」は測れないので、代わりにこれを数える。**先に決めておくのが肝**で、
遊んだ後に基準を作ると、必ず自分に甘くなる。

| 指標 | 通過の線 |
| --- | ---: |
| **R（もう1回）を押した回数** | 10試合中 **7回以上** |
| 試合中に「次はこうしよう」と思った回数 | 1試合あたり **1回以上** |
| 最後まで結果が読めなかった試合 | 10試合中 **4試合以上** |
| 途中で退屈して速度を上げた試合 | 10試合中 **3試合以下** |

**3つ以上が線を割ったら、塊Bに進まない。** ルールを直して塊Aをやり直す。
ここで1ヶ月使うほうが、後で6ヶ月失うより安い。

## 塊B：読み合いの層（5週）

**塊Aを通ってから。** 1つ足すたびに、塊Aの指標を測り直す。

順番は「面白くなる見込みが高い順」。効かない層は**そこで捨てる**。

| | やること | 目安 | なぜこの順か |
| --- | --- | ---: | --- |
| B-1 | **カード3枚。** 詠唱・予兆・クールタイム | 1.5週 | 時計が2本になる。**一番効くはず** |
| B-2 | **見切り 0.3秒。** 相手の詠唱を潰す | 0.5週 | カードが無いと当てる相手が居ない。B-1の後でしか意味を持たない |
| B-3 | **切り札。** 60秒解禁・3秒召喚・寿命 | 1週 | 3本目の時計。あなたの明示的な要望 |
| B-4 | **編成フェーズ。** 6選択＋2抽選・鏡像抽選・commit-reveal | 1.5週 | 試合の外の読み合い。**中が面白くないうちは足しても分からない** |
| B-5 | **アバター6体。** 看板が違うものだけ | 0.5週 | 26特典中21個が未実装。**全部を実装する理由が無い** |

**各工程の終わりに必ず5試合遊ぶ。** 足した層が指標を下げたら、その層を戻す。

**入れないもの**：残り20体の絵、残り20特典、通信、音、収益化。

## 塊C：URLで配る（3週）

**他人が触るまでの摩擦を消す。** ここで「続かない」という2番目の不確実性を潰す。

| | やること | 目安 | 危ないところ |
| --- | --- | ---: | --- |
| C-1 | **pygbag で Web ビルド。** pygame をそのままブラウザで動かす | 1週 | **ここが一番読めない。** 30体同時のWASM性能。1週で動かなければ C-1' に切り替える |
| C-1' | （逃げ道）デスクトップ配布のまま、10人に配る | 0.5週 | 摩擦は残るが日程は守れる |
| C-2 | **非同期対戦。** 入力列を書き出す・読み込む・再生する | 1週 | 決定論が崩れていると再生がズレる。**塊Aの時点で試験を足しておく** |
| C-3 | **共有コード。** 入力列をURLに載せて渡す | 0.5週 | |
| C-4 | **10人に配る。** 何も説明せず渡す | 0.5週 | |

### 判定のしかた

| 指標 | 通過の線 |
| --- | ---: |
| 説明なしで1試合終えられた人 | 10人中 **7人以上** |
| 翌日また開いた人 | 10人中 **3人以上** |
| 相手にコードを送り返した人 | 10人中 **2人以上** |

**2番目の線（翌日また開く）が本命。** ここが割れたら、
足すべきは絵でも量でもなく、**遊ぶ理由**。

### この工程表が間違っているとしたら

- **pygbag が動かない**（C-1）。1週で判定して、駄目ならデスクトップ配布に落とす
- **非同期では物足りない**（C-2）。塊Cの判定で分かる。分かってから通信に6週払えばいい
- **12体では役割の違いが出ない**（3章）。塊Aの6種で先に確かめている
- **塊Aで落ちる**。それは工程表の失敗ではなく、**工程表が仕事をした**ということ
