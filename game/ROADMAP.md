## 0. 前提

見積もりの土台を書いておく。ここが違えば全部の数字がずれる。

| 前提 | 置いた値 | 変わるとどうなる |
| --- | --- | --- |
| 人数 | **プログラム1人** | 2人なら第2期以降が3割ほど縮む |
| 時間 | **週20時間**（土日＋平日夜） | フルタイムなら期間はおよそ半分 |
| 絵 | **別の人に頼む**（第5章） | 自分で描くなら全体が **2倍以上** |
| 音 | 素材購入＋一部発注 | 全部発注なら第4期が1ヶ月伸びる |
| 通信対戦 | **入れる** | 入れないなら第3期がまるごと消えて **4ヶ月短縮** |

**期間はすべて「着手から通過条件を満たすまで」**。手戻りは織り込んでいない。

```

第0期 設計・データ ██
第1期 触れる         ███
第2期 対戦               ███████████
第3期 配る                           ███████████████

────────────────────────────────────────────────────────────
並行：絵                 ███████████████████████████████

```

**およそ1年**（51週）。通信対戦を切れば **8.4ヶ月**。

各期には**通過条件**を1つだけ置く。満たせないうちは次に進まない。
条件を満たせないのは失敗ではなく、そこで**設計を直せという信号**。

| 期 | 通過条件 |
| --- | --- |
| 第1期 | 遊んだ人が **「もう1回」と言う** |
| 第2期 | **同じ相手と5戦して展開が変わる** |
| 第3期 | **知らない人が説明なしで1試合終える** |
| 第4期 | **30分続けて遊べる** |
| 第5期 | 審査を通る |

## 3. 各期の中身

### 第1期 — 触れるようにする（1ヶ月）

**面白いかどうかを最短で確かめる。** それ以外はしない。

| やること | 目安 |
| --- | --- |
| 実時間ループと描画（仮絵をそのまま使う） | 1週 |
| 出撃ボタン・資金バー・拠点HP・成長ボタン | 1週 |
| ユニットは **6種類だけ**（壁・近接・遠距離・後方範囲・速攻・高コスト） | 0.5週 |
| 相手はいまの `policy.py` | 0.5週 |
| 自分で50試合、他人に5人触らせる | 1週 |

**入れないもの**：カード・切り札・アバター特典・編成フェーズ・通信・音。

**作り方**：**Python + pygame をそのまま使う。**
`engine/` が既に動くので、描画と入力を足すだけで済む。ここで Web に移植するのは早い。
*面白いと分かってから*移植する（第3期）。

> 通過条件：**「もう1回」と言うか。**
> 言わないなら、第2期に進んでも同じことになる。ルールを直す。

---

### 第2期 — 対戦として成立させる（3ヶ月）

読み合いの層を1つずつ足す。**足すたびに前の条件を再確認する。**

| やること | 目安 |
| --- | --- |
| カード3枚（詠唱・予兆・クールタイム） | 1.5週 |
| 見切り（0.3秒。詠唱を潰す） | 0.5週 |
| 切り札（60秒解禁・3秒召喚・寿命） | 1週 |
| 編成フェーズ（6選択＋2ランダム・鏡像抽選・commit-reveal） | 1.5週 |
| アバター特典26個 | 3週 |
| ユニット32・カード30を全部入れる | 1週 |
| AI相手を作り直す（いまの方針は粗い） | 2週 |
| 実データでバランス再調整 | 2週 |

**順番が重要**：`README.md` 10章の順番を守る。カードより先に切り札を入れると、
どちらが効いているのか分からなくなる。

> 通過条件：**同じ相手と5戦して、5戦とも展開が変わるか。**
> 同じ手順の繰り返しになるなら、選択肢が足りていない。

**ここで絵の発注を開始する**（第5章）。

---

### 第3期 — 人に配る（3.5ヶ月）

ここが一番重い。**技術的な山場。**

| やること | 目安 |
| --- | --- |
| TypeScript 移植（データJSONは共有のまま） | 4週 |
| Python版との一致試験（同じ種・同じ入力→同じ結果） | 1週 |
| 通信対戦 | 6週 |
| アカウント・戦績保存 | 2週 |
| マッチング | 1.5週 |

**移植の作り方**：Python版を**捨てない**。TypeScript版が本番、
Python版は**バランス計算用の照合器**として残す。両者が一致することを
自動試験にする。これで、balance sweep を高速な Python で回し続けられる。

**通信の作り方**：いまのシミュレータは**すでに決定論的**（固定タイムステップ0.05秒・
浮動小数の比較に EPS）。これは lockstep 方式にそのまま使える条件で、
**設計の副産物として一番大きい資産**。入力だけを送り合えば、
状態を毎フレーム同期しなくてよい。

> 通過条件：**ゲームを知らない人が、説明なしで1試合終えられるか。**

---

### 第4期 — 中身と外側（3ヶ月）

| やること | 目安 |
| --- | --- |
| 本番アートの組み込み（仮絵と差し替え） | 3週 |
| 音（攻撃・被弾・退場・BGM・UI） | 2週 |
| UI仕上げ（編成画面・戦績・設定） | 3週 |
| チュートリアル | 2週 |
| **実プレイのデータでバランス調整** | 4週 |

**バランス調整は第4期が本番。** 第2期のはシミュレータ相手の机上のもので、
人間は必ず想定外の遊び方をする。ここで `README.md` 11章の未決の論点
（成長の導入・カードを撃たない理由・rushの弱さ）に**実データで答えが出る**。

> 通過条件：**30分続けて遊べるか。**

---

### 第5期 — 出す（1ヶ月）

| やること | 目安 |
| --- | --- |
| 収益化の実装 | 2週 |
| ストア申請・レーティング（CERO/IARC） | 2週 |
| 利用規約・プライバシーポリシー | 1週 |
| 問い合わせ窓口・不具合報告 | 0.5週 |

**課金は見た目だけにする。** `README.md` 11章の結論の通り、
アバターを課金で買えるようにすると「金で情報を買う」形になり、
7.1で置いた原則（特典は勝敗ではなく手順を変える）が壊れる。
**全アバターを無料開放**し、課金は色替え・エフェクト・称号に寄せる。

## 4. 先に決めないと進めない3つ

| 決めること | いつまで | 選択肢 | 推す案 |
| --- | --- | --- | --- |
| **出す場所** | 第3期の開始前 | Web / スマホ / Steam | **Web先行。** URLで配れるのでテストの摩擦が最小。スマホへは後から包める |
| **1人用を入れるか** | 第2期の開始前 | 無し / CPU戦のみ / ステージ制 | **CPU戦のみ。** ステージ制は制作量がもう1本増える |
| **収益化** | 第4期の開始前 | 買い切り / 見た目課金 / 広告 | **見た目課金。** 上の理由で性能に触れない |

**「1人用を入れるか」を第2期の前に決める理由**：入れるなら AI 相手の作り込みが
「テスト用」から「商品」に変わる。第2期の2週が5週になる。

## 5. 絵が最長路になる

**制作量の大半は絵で、それが全体の期間を決める。**

| | 数 | ×枚 | 合計 |
| --- | ---: | ---: | ---: |
| ユニット | 32 | 13 | 416 |
| 切り札 | 3 | 13 | 39 |
| アバター（崩れ3段階） | 12 | 3 | 36 |
| カードのアイコン | 30 | 1 | 30 |
| エフェクト | 〜20 | 6 | 120 |
| **計** | | | **641枚** |

| 進み方 | 期間（1人） |
| --- | --- |
| 1日4枚 | **7.5ヶ月** |
| 1日6枚 | **5ヶ月** |
| 1日8枚 | 3.7ヶ月 |

**本番アートの組み込みは第4期（M9）に始まる。間に合わせるには、
遅くとも第2期の開始（M2）に発注する。**
M2 に出しても、1日4枚では M9.5 ―― **半月ほど足りない**。
1日6枚なら M7 に上がるので余裕がある。**発注の速度がそのまま全体の期限になる。**

**いま発注できる。** 32体の役割と数字は確定していて（`data/characters.json`）、
シルエットの規約は文章と**動く生成器の両方**で示してある（`art/README.md` 3章、
`tools/sprites.py`）。絵描きに渡すものが既に揃っている状態。

**発注の単位**：1体ずつ、ラフ（シルエットのみ）→ ドット → アニメ13枚。
ラフの段階で `art/README.md` 3章の規約に合っているかを見る。
ここで弾けば、13枚描いた後のやり直しが無くなる。

## 6. 危ないところ

| 危険 | 兆候 | どうするか |
| --- | --- | --- |
| **面白くない** | 第1期で「もう1回」が出ない | **第1期を延ばす。** 先に進まない。ここで1ヶ月使うほうが、後で6ヶ月失うより安い |
| **絵が間に合わない** | M4 時点で100枚を切っている | 発注を分割して2人にする。または切り札とエフェクトを削って初回配信の範囲を狭める |
| **通信で溶ける** | 第3期が6週を超える | **通信を切る。** 非同期対戦（相手の入力を記録して後から再生）に落とせば決定論がそのまま効く |
| **バランスが収束しない** | 第4期で勝率が偏り続ける | データがJSONなので**再配信なしで直せる**構造にしておく（第3期でサーバ配信にする） |
| **一人で息切れ** | 第3期が長い | 第3期の前で一度**遊べる形で公開**する（第2期の成果をローカル対戦として配る） |

**いちばん現実的な危険は最後の2つ。** 11ヶ月は長い。
第2期の終わりに一度「人に見せられるもの」を出すのが、続けるための保険になる。

## 7. 今週やること

1. **`engine/` に描画を足す。** `battle.py` の `step()` を実時間で回して、
   `art/out/units/*.png` をレーン上に並べるだけ。入力はまだ無くていい。
2. **出撃ボタンを1つ付ける。** 兵卒だけ。押したら出る。
3. **資金バーと拠点HPを画面に出す。** 数字が見えるだけでいい。
4. **6種類に絞った試遊用のデータを作る。** `data/characters.json` から抜く。
5. **自分で10試合遊ぶ。** 面白いかどうかの最初の手触りを取る。

**この5つで、第1期の通過条件を測る土台ができる。**
順番はこの通りで、1つずつ動くところまで持っていく。

| 期 | 週 | 累計 |

| 第1期 触れる | 4 | 4 |
| 第2期 対戦 | 13 | 17 |

**51週 ≒ 11.7ヶ月**（週20時間 ＝ およそ1020時間）。

1人用も切ると、**さらに短い**が、その場合「誰と遊ぶのか」が残る。
